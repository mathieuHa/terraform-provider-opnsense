# OPNsense provider for OpenTofu and Terraform

Manage OPNsense® firewalls as code through the OPNsense API: firewall rules and aliases, NAT, interfaces, VPNs, DHCP, DNS, routing, high availability, intrusion detection and plugins such as HAProxy, Caddy and the ACME client.

**Documentation: <https://mathieuha.github.io/terraform-provider-opnsense/>** — [quickstart](https://mathieuha.github.io/terraform-provider-opnsense/quickstart/), [guides](https://mathieuha.github.io/terraform-provider-opnsense/guides/singletons/) and the [list of supported resources](https://mathieuha.github.io/terraform-provider-opnsense/resources/).

> [!WARNING]
> Until v1.0, resource and data source schemas may change between minor releases. Read the [release notes](https://github.com/mathieuHa/terraform-provider-opnsense/releases) before upgrading.

## Example usage

```hcl
terraform {
  required_providers {
    opnsense = {
      source  = "mathieuHa/opnsense"
      version = "~> 0.37"
    }
  }
}

provider "opnsense" {}

resource "opnsense_firewall_alias" "admins" {
  name    = "admins"
  type    = "network"
  content = ["10.0.50.0/24"]
}

resource "opnsense_firewall_filter" "admins_https" {
  description = "Admins to the web GUI"
  interface   = { interface = ["lan"] }
  filter = {
    action      = "pass"
    direction   = "in"
    protocol    = "TCP"
    source      = { net = opnsense_firewall_alias.admins.name }
    destination = { net = "(self)", port = "https" }
  }
}
```

The empty `provider` block reads `OPNSENSE_URI`, `OPNSENSE_API_KEY` and `OPNSENSE_API_SECRET` from the environment. The provider is published on the [OpenTofu registry](https://search.opentofu.org/provider/mathieuha/opnsense). With Terraform, use `source = "registry.opentofu.org/mathieuha/opnsense"`.

## About this fork

This repository is a maintained fork of [browningluke/terraform-provider-opnsense](https://github.com/browningluke/terraform-provider-opnsense). It extends the API coverage, publishes signed releases with release notes, and runs the acceptance suite against real OPNsense instances before each release. Resource and attribute names follow upstream, so existing configurations only need the new provider source.

## Repository layout

- [`docs/`](./docs/) — resource reference, generated by `go generate` from the schemas, [`templates/`](./templates/) and [`examples/`](./examples/).
- [`examples/guides/`](./examples/guides/) — the configurations shown in the documentation guides.
- [`site/`](./site/) — the documentation site, built from `docs/` and `examples/` and published to GitHub Pages on every push to `main`.
